## Expresso

### Concepts / rappels

1. **Plugin** — un paquet installable en une commande qui peut apporter des Skills, des agents, des hooks ou un serveur MCP à Claude Code.
2. **Marketplace** — un catalogue de plugins. Il en existe trois sortes : l'officielle (`claude-plugins-official`, curée par Anthropic), la communautaire (`claude-plugins-community`, validée automatiquement), et n'importe quel dépôt GitHub public qui contient son propre `marketplace.json`.
3. **Connecteur** — un plugin qui expose, via MCP, les outils d'un service tiers (boîte mail, gestionnaire de tickets...) directement dans la conversation.

### Questions

1. Qui a déjà tapé `/plugin` dans Claude Code — juste pour voir ce qu'il y avait dedans ?

## Presentations

### 1. Marketplace de plugins Claude Code : Skills et connecteurs

> Une commande, un plugin, et Claude parle déjà à vos outils.

**Le principe**

Claude Code s'étend par plugins : chacun peut ajouter des Skills, des agents, des hooks ou un serveur MCP. Un connecteur est un plugin particulier — il branche Claude Code sur un service tiers via MCP, et les actions de ce service (lire un email, créer un ticket) deviennent des outils utilisables dans la conversation, sans quitter le terminal. On les installe depuis une marketplace, catalogue de plugins ajouté avec `/plugin marketplace add`.

**Partie 1 — Plugins officiels : Agentmail et Linear**

Démo de deux connecteurs listés dans la marketplace officielle `claude-plugins-official` :

- **Agentmail** — donne à Claude Code l'accès à une boîte mail agentique : lire les messages entrants, rédiger une réponse, envoyer — le tout piloté en langage naturel.
  *Ex : « Résume les emails non lus de ce matin et prépare un brouillon de réponse pour les trois qui demandent un devis. »*
- **Linear** — expose le gestionnaire de tickets Linear : lister les issues, en créer une nouvelle, la faire passer d'un statut à l'autre, directement depuis la conversation.
  *Ex : « Crée un ticket Linear à partir de ce bug remonté par email, priorité haute, assigné à l'équipe backend. »*

```
/plugin marketplace add anthropics/claude-plugins-official
/plugin install agentmail@claude-plugins-official
/plugin install linear@claude-plugins-official
```

**Partie 2 — Bonus : un plugin tiers depuis un simple dépôt GitHub**

Pas besoin d'être listé dans une marketplace officielle ou communautaire : un dépôt GitHub public portant un `.claude-plugin/marketplace.json` suffit. Démo avec le dépôt [mikamboo/agent-skills](https://github.com/mikamboo/agent-skills) et sa Skill `business-presentation`, qui transforme une simple description d'idée en une présentation business complète (HTML/PDF) — étude de marché, financials, SWOT, roadmap — après une phase de recherche web pour ancrer le contenu dans des données réelles.
*Ex : « J'ai une idée de café-resto à Vieux-Habitants, en Guadeloupe — prépare-moi un dossier de présentation pour mon rendez-vous banque. »*

```
/plugin marketplace add mikamboo/agent-skills
/plugin install business-skills@kevatech-agent-skills
```

**Le déroulé**

- Installation des connecteurs Agentmail et Linear depuis la marketplace officielle
- Lecture d'un email et création d'un ticket Linear correspondant, en une conversation
- Ajout de la marketplace tierce `mikamboo/agent-skills` et installation du plugin `business-skills`
- Génération en direct d'une présentation business à partir d'une idée dite à voix haute

**Ce qu'on retient**

- Un connecteur, ce n'est rien d'autre qu'un plugin qui parle MCP à un service externe — pas de mécanisme caché.
- La marketplace officielle est curée ; la communautaire est validée automatiquement ; un dépôt GitHub perso n'a besoin que d'un `marketplace.json` pour jouer le même rôle.
- Une Skill installée par un plugin se déclenche toute seule dès que la conversation correspond à sa description — pas de commande à mémoriser.

**Cas d'usage typiques**

Centraliser la gestion des emails et des tickets sans changer d'outil, ajouter une compétence métier précise (présentation, rédaction, génération de document) en une commande, partager en interne un pack de Skills spécifique à son entreprise via un simple dépôt GitHub.

### 2. Claude Design : synchroniser son Design System

> Vos vrais composants, pas des maquettes génériques.

**Le principe**

`/design-sync` convertit le Design System React d'un repo et l'envoie vers [Claude Design](https://claude.ai/design) (`claude.ai/design`) : les designs que Claude produit ensuite réutilisent vos composants réels, plutôt que d'improviser une palette et une mise en page génériques. `/design-login` autorise l'accès une première fois depuis le compte claude.ai. Un premier sync vérifie chaque composant un par un et peut prendre plusieurs heures sur un gros repo.

```
/design-login
/design-sync
```

Présentée par Xavier Gueret, qui prend la main sur son contenu.

## Glossaire

- **Plugin** — paquet installable en une commande, pouvant apporter Skills, agents, hooks ou serveur MCP à Claude Code.
- **Marketplace** — catalogue de plugins ; officielle, communautaire, ou tout dépôt GitHub avec son `marketplace.json`.
- **Connecteur** — plugin qui expose, via MCP, les outils d'un service tiers dans la conversation.
- **MCP (Model Context Protocol)** — protocole standard par lequel un modèle appelle les outils d'un service externe.
- **Skill** — compétence packagée qui se déclenche automatiquement quand la conversation correspond à sa description, sans commande à retenir.
- **Design System (Claude Design)** — la bibliothèque de composants React d'un projet, synchronisée vers `claude.ai/design` via `/design-sync` pour que les designs générés réutilisent les vrais composants plutôt qu'une maquette générique.
